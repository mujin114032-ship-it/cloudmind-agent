# CloudMind-Agent 阶段性进展

## 第一阶段：基础 RAG 闭环

第一阶段主要完成知识库问答系统的最小可用闭环，实现从文档上传到智能问答的完整链路。

**已完成能力包括：**

1. 知识库 CRUD
2. 文档上传与文档列表管理
3. 文档解析与文本分块
4. 本地 BGE Embedding 服务接入
5. 文档分块批量向量化
6. Milvus 向量库写入与检索
7. 知识库检索测试
8. 普通 RAG 问答接口
9. SSE 流式 RAG 问答接口
10. 前后端基础联调

**核心链路如下：**

文档上传 ➔ 文档解析 ➔ 文本分块 ➔ Embedding 向量化 ➔ Milvus 向量入库 ➔ 用户问题向量化 ➔ 语义检索 ➔ Prompt 组装 ➔ 大模型回答 ➔ 前端展示答案与参考片段

---

## 第二阶段：RAG 工程化增强

第二阶段主要围绕 RAG 的可观测性、稳定性、检索质量和用户体验进行增强，使系统从基础 Demo 进一步升级为更接近真实业务场景的知识库问答系统。

### 1. RAG Trace 链路追踪

新增 RAG Trace 机制，用于记录一次问答的完整执行链路，包括：

* 原始问题
* 改写问题
* 检索参数
* 召回片段
* Prompt 内容
* 大模型回答
* 检索耗时
* 生成耗时
* 总耗时
* Prompt 版本
* 执行状态
* 错误信息

该功能用于定位回答质量问题，例如判断问题出在 Query Rewrite、向量检索、Prompt 设计还是大模型生成阶段。

### 2. 异步文档向量入库任务

将文档向量化与 Milvus 入库改造为异步任务模式。

**原同步流程：**

用户点击入库 ➔ 请求线程等待 Embedding + Milvus 写入完成 ➔ 返回结果

**优化后流程：**

用户点击异步入库 ➔ 创建 document_ingest_task ➔ 立即返回 taskId ➔ 后台线程执行向量化与 Milvus 写入 ➔ 前端轮询任务状态 ➔ 展示入库进度与结果

该功能避免了大文件入库时前端长时间等待，也支持页面返回后重新进入时恢复入库状态。

### 3. 会话与消息持久化

新增聊天会话能力，使问答页面从临时测试页升级为真实的对话式知识库问答页面。

**已支持：**

* 创建会话
* 查询会话列表
* 查询历史消息
* 保存用户消息
* 保存 AI 回答消息
* 保存回答引用片段
* 绑定 RAG Trace
* 刷新页面后恢复聊天记录

**会话链路如下：**

用户进入知识库 ➔ 创建或选择会话 ➔ 发送问题 ➔ 保存 user message ➔ SSE 流式生成 assistant message ➔ 保存 AI 回答、引用片段与 traceId ➔ 历史消息可回显

### 4. 会话 SSE 流式问答

在会话场景下接入 SSE 流式 RAG 问答，实现边生成边展示，并在生成结束后持久化完整 AI 消息。

**主要事件包括：**

* message_created
* retrieval_start
* retrieval_done
* answer_start
* answer_delta
* answer_done
* error

该功能提升了长回答场景下的交互体验，避免普通 HTTP 问答因大模型生成时间较长导致前端超时。

### 5. Query Rewrite 问题改写

新增 Query Rewrite 能力，在检索前将用户问题改写为更适合知识库检索的独立问题。

**示例：**

* **原始问题：**这篇论文叫什么？
* **改写问题：**高分六号卫星的交叉辐射定标研究这篇论文的标题是什么？

对于会话场景，系统会结合最近历史消息补全指代关系，提高连续追问时的检索稳定性。

### 6. Query Rewrite 历史门控

为避免跨话题提问时错误引入历史上下文，新增历史使用门控机制。

系统会判断当前问题是否真的需要历史上下文：

**需要历史：**

* 它用了什么方法？
* 这篇论文叫什么？
* 结论呢？
* 这个方法有什么优点？

**不需要历史：**

* 前端如何更新？
* 后端怎么部署？
* Milvus 怎么启动？
* Redis 怎么配置？

该机制避免了“上一轮问交叉定标，下一轮问前端更新”时被错误改写成“交叉定标中的前端系统如何更新”。

### 7. 相邻 Chunk 扩展

新增相邻 Chunk 扩展能力，用于补充命中分块前后的上下文。

**原流程：**

Milvus 命中 chunk ➔ 直接进入 Prompt

**优化后：**

Milvus 命中 chunk ➔ 扩展前后相邻 chunk ➔ 去重与截断 ➔ 进入 Prompt

该功能适合论文、报告等连续叙述型文档，可以缓解“命中片段只包含部分信息”的问题，使回答从局部概括提升为更完整的上下文分析。

### 8. 检索结果去重与过滤

新增检索结果过滤策略，用于控制最终进入 Prompt 的上下文质量。

**主要规则包括：**

* 低分过滤
* 重复 chunk 去重
* 限制单篇文档直接命中数量
* 相邻扩展结果二次去重
* 限制最终上下文 chunk 数量

该功能避免同一篇文档或重复片段占满上下文窗口，降低无关或低质量片段对回答的干扰。

### 9. Prompt 版本管理

新增 Prompt 模板版本管理能力，并支持前端用户选择回答风格。

**当前支持模板：**

* basic-v1 基础问答
* strict-v1 严格知识库问答
* concise-v1 简洁回答
* academic-v1 学术论文分析

**设计方式：**

后端注册 Prompt 模板 ➔ 前端查询可用模板 ➔ 用户选择 promptVersion ➔ 请求携带 promptVersion ➔ 后端校验并构造 Prompt ➔ Trace 记录实际使用版本

这样既保证了前端使用灵活性，也避免前端直接传完整 Prompt 带来的安全和不可控问题。

### 10. 回答后处理
新增 AnswerPostProcessor，对大模型输出做轻量清洗。
**处理内容包括：**
* 去除首尾空白
* 压缩多余空行
* 去除“回答：”“答案：”等无意义前缀
* 空回答兜底
* 保留模型原始语义

该功能只做轻量格式整理，不重写回答内容，避免破坏模型生成结果。

## 后续计划
后续可以继续增强以下方向：
1. Reranker 重排，提高召回片段排序质量。
2. Hybrid Search，引入关键词检索与向量检索融合。
3. 文档来源扩展，为接入 LabLink 云盘文件做准备。
4. OCR 解析支持，处理扫描版 PDF。
5. Prompt 模板数据库化，支持用户自定义模板。
6. LabLink 接入，实现云盘文件一键加入知识库。
